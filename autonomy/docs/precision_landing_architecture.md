# Precision Landing Architecture

This document describes the upgraded multi-process precision landing logic utilized by the SkyLink Companion Computer.

## Overview
The precision landing system manages the drone's descent by actively resolving ArUco marker geometry using the companion computer's vision pipelines, translating the resulting spatial offsets into velocity/position corrections.

## Multi-Process Queue Pattern
To ensure the vision processing loop (which can drop to 15-20 FPS) does not block the high-frequency MAVLink network loop or the PID controllers, SkyLink adopts a multi-process queue pattern decoupled across distinct runtimes:

1. **Vision Ingestion (Producer)**
   - The camera stream continuously yields frames to `ArucoBoardDetectorBackend`.
   - Vision detection identifies multiple markers on the board and extracts robust `rvec`/`tvec` poses.
   - Resulting spatial `LandingTargetObservation` structs are fired into a thread-safe Queue or `sender.send()` socket.

2. **Control Translation (Consumer)**
   - On the drone side, `precision_landing.py` evaluates the error (distance from target).
   - Offsets are pushed directly through local `PIDController`s to compute real-time XYZ velocities.
   - By isolating CV from telemetry, camera latency spikes prevent complete PID instability.

## FSM State Machine Integration
The `PrecisionLandingController` FSM phases remain in command:
- **SEARCH**: No targets identified; hold altitude or gently yaw to acquire.
- **ALIGN**: Target acquired horizontally; execute rapid X/Y offsets to zero out deviation.
- **DESCEND**: Drone is aligned within `PLD_HACC_RAD`; steadily decrease `z_val`.
- **FLARE**: Drone approaches ground effect (`flare_altitude_m`); descent slows while aggressive P-gains maintain center hold.
- **TOUCHDOWN**: Drone senses altitude < `touchdown_altitude_m` and neutralizes all thrust to settle.

## LANDING_TARGET Bridging
To maintain strict PX4 SITL/HITL parity without fully hijacking the drone with completely autonomous custom commands, local coordinate targets generated by the Board Detector are still packed mathematically into standard MAVLink `LANDING_TARGET` network messages and piped by `pymavlink` to the flight controller. This ensures PX4's internal `RTL_PLD_MD` abort logic functions correctly if the radio link fails.
